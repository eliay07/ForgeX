# 产品视觉母版与素材协议

借鉴游戏制作的“统一视觉母版”，产品设计必须先确定完整体验的视觉语言，再拆解页面、组件和素材。产品不是只生成一张首页图，而是生成一组关键状态。

## 1. Product Identity 与 Visual DNA

至少定义：产品人格、目标人群、品牌承诺、形状语言、色彩角色、字体层级、图标语言、界面密度、表面材质、动效节奏、影像语言和禁用项。

若有外部参考，生成 3 个候选方向并注明：借鉴什么、不借鉴什么、适配风险和实现成本。不得临摹商标、专有角色或独特构图。

## 2. 关键状态组母版

视觉设计前先从 User Flow 选择 4 到 8 个关键状态，通常包括：

- 第一次进入或输入入口。
- 核心任务进行中。
- 需要用户判断的关键 Gate。
- 成功结果或交付。
- 一个高风险错误或恢复状态。
- 桌面与移动端的关键差异状态。

使用 GPT 图像生成或设计工具时，每张图只表现一个状态。所有图共享同一 Visual DNA、导航模型、组件语言和信息优先级。

## 3. 母版检查

- 第一焦点是否对应当前主任务。
- 主动作是否稳定且不与次要操作竞争。
- 相邻状态是否像同一个产品，而非不同模板。
- 信息密度是否匹配目标用户与任务频率。
- 内容较长时是否通过目录、分段、摘要、折叠和深层详情处理。
- 图片中的结构是否能够用真实组件和布局实现。

未通过时修改 Visual DNA 或页面结构。不得在未选定方向时批量生成最终素材。

## 4. 素材拆解

| 类型 | 适用 | 默认实现 |
|---|---|---|
| Brand | Logo、应用图标、社交封面 | 矢量源文件或高分辨率 bitmap |
| Product imagery | 真实对象、场景、主要界面概念 | GPT 图像生成、真实截图或摄影 |
| Illustration | 空状态、引导、解释复杂概念 | 统一风格 bitmap/矢量素材 |
| UI icon | 操作、导航、状态 | 既有图标库，例如 Lucide |
| UI control | 按钮、输入、Tab、菜单、面板 | React/Vue 等真实 DOM 组件 |

不得把按钮、表单、菜单或长文排版生成为不可交互图片。生成素材要保存提示词、来源、用途和版本。
