# 产品 QA 与真实用户路径验证

## 1. 先写测试用例

每个核心目标至少覆盖：

- Happy Path。
- 无数据或首次使用。
- 输入错误或服务失败。
- 中断、刷新、返回和继续。
- 权限不足或危险操作取消。
- 移动端窄屏和桌面端。

测试用例写明 Persona、起始状态、目标、步骤、期望、证据和对应 Feature/Artifact。

## 2. 浏览器验证

1. 启动真实应用，确认第一个可操作页面。
2. 像目标用户一样完成端到端任务，不能只调用内部接口。
3. 对关键状态截图，并检查 DOM、网络、控制台和持久化结果。
4. 视觉检查必须覆盖溢出、遮挡、层级、焦点、文本完整、交互反馈和空白页面。
5. 对长任务验证可观测事件、心跳、暂停、失败、重试和恢复。

推荐至少测试 `390x844`、`768x1024`、`1440x900`；固定格式画布需增加其目标比例。

## 3. 自动修复循环

```text
执行测试 -> 记录 Issue -> 定位责任 Artifact/模块 -> 最小修复
-> 运行定向测试 -> 运行受影响主路径回归 -> 保存新证据
```

最多自动循环三轮。反复失败、产品方向冲突、数据破坏风险或需要用户偏好的问题升级为人工 Gate。

## 4. 报告顺序

先列 Blocker/High findings，再列验证通过项。每条问题写用户看到什么、复现步骤、影响、责任模块和证据路径。
