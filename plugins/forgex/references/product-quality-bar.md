# 通用产品质量基线

## 1. 产品质量

- 用户不读方法论说明，也知道当前要做什么、下一步是什么。
- 每个主要页面只有一个主任务和一个 Primary Action。
- 每个 Feature 可追溯到用户问题、目标用户、User Flow、Page、数据契约和验收条件。
- 空、加载、错误、权限、取消、保存、恢复和重试均有明确状态。
- 所有复杂性按使用频率、价值、风险和上下文渐进披露。

## 2. 视觉质量

- 先定义产品身份与完整关键状态组，再实现单个组件。
- 页面层级、焦点、密度、留白和阅读顺序清楚；不使用同权重模块堆叠。
- 视觉资产、字体、图标、颜色、动效和界面表面共享同一 Visual DNA。
- 不使用默认 AI 套件感：无意义渐变、装饰光球、过量大圆角、随机卡片流和解释型 UI 文案。
- 图像用于表达真实产品、对象或状态，不代替可交互 DOM 控件。

## 3. 工程质量

- 真实数据路径与 UI 行为闭环；不以假按钮和静态成功状态充数。
- 核心领域状态与渲染层分离；接口、错误、权限和幂等有契约。
- 复用仓库既有模式；局部变更不引入无关重构。
- 构建、类型检查、单元测试和浏览器主路径验证通过。

## 4. 完成定义

只有同时满足以下条件才可以说完成：

1. 用户主路径从真实入口运行到真实结果。
2. 至少一个代表性异常路径可以恢复。
3. 桌面与移动端关键页面无溢出、遮挡或不可达操作。
4. QA 证据已保存，Blocker/High Issue 已关闭或由用户接受风险。
5. 交付包可打开，且内容来自已批准 Artifact。
